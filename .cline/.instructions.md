# IGCLWrapper Guide

## Overview

The IGCLWrapper project provides a comprehensive C# wrapper for the Intel Graphics Control Library (IGCL) SDK to allow the native Intel ControlLib.dll to be used within C#. The IGCLWrapper uses **ClangSharp** to automatically generate P/Invoke bindings directly from the IGCL C headers. The IGCLWrapper enables application developers to have full access to the IGCL functionality from their C# applications, including GPU management, display control, performance monitoring, and tuning capabilities.

The IGCLWrapper will primarily be used within the DisplayMagician application to provide access to the Intel GPU and Display Management functionality so that the DisplayMagician software can control Intel GPUs, and can read and store their settings.

## Project Tech Stack

### Programming Language

This project is written in C# (.NET 8) with ClangSharp-generated P/Invoke bindings.

#### ClangSharp

This project uses **ClangSharp** (https://github.com/dotnet/ClangSharp) to automatically generate C# P/Invoke bindings directly from the IGCL C headers.

**Key Benefits:**
- No intermediate C++ wrapper DLL needed
- Direct P/Invoke calls to Intel's ControlLib.dll
- Bindings auto-generated from igcl_api.h
- Type-safe, high-performance interop
- Automatic synchronization with IGCL updates

**Configuration:**
- `IGCLWrapper/ClangSharpConfig.rsp` - ClangSharp generation settings
- `IGCLWrapper/IGCLWrapper.csproj` - MSBuild integration with ClangSharpPInvokeGenerator

**Generated Output:**
- `IGCLWrapper/IGCL.cs` - Auto-generated P/Invoke bindings (**DO NOT EDIT MANUALLY**)

#### C#

The project consists of:
- **IGCL.cs** - Auto-generated P/Invoke bindings (ClangSharp output)
- **IGCLExtensions.cs** - Manual extension methods and helper utilities
- **IGCLApi.cs** - High-level managed wrapper with exception handling
- **IGCLHelpers.cs** - Common utilities and type conversions

### Intel IGCL SDK

This project's main aim is to provide C# bindings for the Intel IGCL SDK. The Intel IGCL SDK is downloaded and placed into the 'drivers.gpu.control-library' folder by the prepare_igcl.ps1 powershell script.

The IGCL functionality is described most accurately within the **drivers.gpu.control-library/include/igcl_api.h** file. This is a C header file that lists the functionality available within the IGCL, and it should be considered your **primary source of information** about the IGCL. There is also a drivers.gpu.control-library/Samples/inc/GenericIGCLApp.h header file which also has some helpful content that will be useful to understand how to access and setup the IGCL library for use.

You can view documentation about the IGCL at https://intel.github.io/drivers.gpu.control-library/. This should be your secondary source of information about the IGCL.

You should also review the C/C++ samples in the drivers.gpu.control-library/Samples folder too as they will be useful for you to know, and will show you how to test the IGCL functionality.

### .NET and MSBuild

This project uses .NET 8.0 SDK and MSBuild for compilation. The project should be able to build within Visual Studio 2022, Visual Studio Code, and via command-line using `dotnet` CLI.

## Architecture (ClangSharp Migration)

### Direct P/Invoke Approach

The project uses a direct P/Invoke approach with no intermediate C++ wrapper:

1. **ClangSharp** reads `igcl_api.h` and generates `IGCL.cs`
2. **IGCL.cs** contains raw P/Invoke declarations for ControlLib.dll
3. **IGCLExtensions.cs** adds extension methods for usability
4. **IGCLApi.cs** provides high-level managed API with error handling
5. Applications use `IGCLApi` class for safe, managed access

### File Responsibilities

1. **IGCL.cs** (Auto-generated - **DO NOT EDIT MANUALLY**)
   - Raw P/Invoke function declarations
   - Struct definitions matching C layout
   - Enums and constants
   - Function pointer delegates
   - **Regenerated automatically on build when headers change**
   - Any manual changes will be lost on next build

2. **IGCLExtensions.cs** (Manual)
   - Extension methods for generated types
   - String marshaling helpers
   - Safe handle wrappers for pointers
   - Convenience methods for common patterns

3. **IGCLApi.cs** (Manual)
   - High-level API facade
   - Exception handling (IGCLException)
   - Resource management (IDisposable pattern)
   - Simplified method signatures
   - Memory safety guarantees

4. **IGCLHelpers.cs** (Manual - if needed)
   - Utility methods
   - Type conversions
   - Common patterns and helpers

## Project and Code Guidelines

### Critical Rules

- **CRITICAL: ALWAYS ASK THE USER FOR PERMISSION IF THE ORIGINAL STRATEGY THE USER APPROVED DOESN'T WORK AND YOU WANT TO CHANGE THE STRATEGY YOU USE TO ACHIEVE THE OUTCOME. THE USER MUST APPROVE THAT CHANGE.**

- **CRITICAL: DO NOT MODIFY IGCL.cs DIRECTLY!**
  - IGCL.cs is auto-generated by ClangSharp
  - Changes to bindings must be made via ClangSharpConfig.rsp
  - Manual fixes and extensions go in IGCLExtensions.cs
  - Regenerate bindings by building the project: `dotnet build`

- **CRITICAL: Never remove IGCLWrapper functionality without asking for permission to do so!**
  - This means NEVER remove public APIs from IGCLApi.cs without user approval
  - Do NOT delete extension methods from IGCLExtensions.cs without permission

### General Guidelines

- After you have made changes to ClangSharpConfig.rsp, always rebuild to regenerate IGCL.cs
- Never truncate large files. If you find that you have truncated a file and have lost some functionality then restore the file back to where it has the full functionality back and then try again.
- Always use type hints in any language which supports them (C# nullable reference types enabled)
- All public types should be serializable to JSON using System.Text.Json or Newtonsoft.Json
- Unit tests are required, and are required to pass before PR passes
  - Unit tests should focus on core functionality
  - Unit tests should be made in xUnit.net, and should be tested in .NET 8
  - Tests are in IGCLWrapper.Tests project
- Always follow good security practices
  - Use safe pointer handling (SafeHandle where appropriate)
  - Validate all inputs before P/Invoke calls
  - Dispose resources properly (IDisposable pattern)
- Always update documentation if you change functionality
- When using the terminal to execute commands, always remember you are running within a PowerShell Terminal on a Windows 11 PC
- Do not use older Command Terminal commands - use PowerShell or `dotnet` CLI commands instead

## ClangSharp Configuration

### ClangSharpConfig.rsp

The `ClangSharpConfig.rsp` file controls how ClangSharp generates bindings:

```
--file igcl_api.h                    # Source header file
--namespace IGCLWrapper              # C# namespace for generated code
--output IGCL.cs                     # Output file name
--methodClassName IGCL               # Static class name for P/Invoke methods
--libraryPath ControlLib.dll         # DLL name for [DllImport]
--config compatible-codegen          # Generate compatible code
--include-directory ../drivers.gpu.control-library/include
```

### Customizing Bindings

If you need to modify how bindings are generated:

1. Edit `IGCLWrapper/ClangSharpConfig.rsp`
2. Rebuild the project: `dotnet build IGCLWrapper/IGCLWrapper.csproj`
3. ClangSharp will regenerate `IGCL.cs` automatically
4. **Never** edit `IGCL.cs` directly - changes will be lost!

### Adding Manual Extensions

For additional functionality or workarounds:

1. Add methods to `IGCLExtensions.cs` (extension methods)
2. Add helper methods to `IGCLApi.cs` (high-level API)
3. **Do NOT** edit `IGCL.cs` - it will be overwritten

## Troubleshooting

### Bindings Not Regenerating

**Problem:** Changes to igcl_api.h or ClangSharpConfig.rsp don't update IGCL.cs

**Solution:**
```powershell
# Clean build artifacts
dotnet clean

# Delete obj and bin folders
Remove-Item -Recurse -Force IGCLWrapper\obj, IGCLWrapper\bin

# Rebuild
dotnet build IGCLWrapper/IGCLWrapper.csproj
```

### P/Invoke DllNotFoundException

**Problem:** `DllNotFoundException: Unable to load DLL 'ControlLib.dll'`

**Solution:**
1. Ensure ControlLib.dll is in the application output directory
2. Check that IGCL SDK is properly installed in `drivers.gpu.control-library/bin/`
3. Verify DLL is copied to test output: `IGCLWrapper.Tests/bin/Debug/net8.0/`
4. On test machines, ensure Intel graphics drivers are installed

### Struct Layout Mismatches

**Problem:** Access violations or incorrect data returned

**Solution:**
1. Verify ClangSharp generated correct struct layouts in IGCL.cs
2. Check for packing/alignment issues (compare with C headers)
3. Add explicit `[StructLayout(LayoutKind.Sequential)]` if needed
4. Report issues to ClangSharp if auto-generation is incorrect

### Type Marshaling Issues

**Problem:** String marshaling errors or pointer issues

**Solution:**
1. Add custom marshaling to IGCLExtensions.cs
2. Use `[MarshalAs(UnmanagedType.LPStr)]` for string parameters
3. Consider SafeHandle for pointer lifetime management
4. Wrap unsafe operations in IGCLApi.cs with safe wrappers

### Build Errors After Header Updates

**Problem:** Compilation errors after updating igcl_api.h

**Solution:**
1. Regenerate bindings (clean + rebuild)
2. Update IGCLExtensions.cs to match new API signatures
3. Update IGCLApi.cs wrapper methods
4. Update tests to match new API behavior

This project has been migrated from SWIG to ClangSharp for better maintainability and performance.

**Key Changes:**
- No C++ wrapper layer (direct P/Invoke)
- Auto-generated bindings from headers
- Better type safety and performance
- Easier to maintain and update
- Native .NET 8 integration

**Legacy References:**
- All SWIG-related files are obsolete
- Old `rebuild_igcl.bat` scripts no longer used

### ? Current Blocker: COMPILATION ERRORS

#### Problem Summary
The test files have **133+ compilation errors** due to type mismatches between:
1. ClangSharp-generated pointer types (`_ctl_device_adapter_handle_t*`, `_ctl_display_output_handle_t*`, etc.)
2. Test expectations using `IntPtr` and `IntPtr[]`

#### Specific Issues Identified

**Issue 1: EnumerateAdapters() Return Type**
```csharp
// Tests expect:
IntPtr[] adapters = _api.EnumerateAdapters();

// But ClangSharp likely generates:
_ctl_device_adapter_handle_t*[] adapters = _api.EnumerateAdapters();
```

**Issue 2: Handle Type Conversions**
```csharp
// Tests call:
IGCL.ctlEnumEngineGroups(_adapters[0], &count, null);

// Error: Cannot convert from 'nint' to 'IGCLWrapper._ctl_device_adapter_handle_t*'
```

**Issue 3: Missing Version Macros**
```csharp
// Tests use:
IGCL.CTL_MAKE_VERSION(1, 1)
IGCL.CTL_MAJOR_VERSION(version)
IGCL.CTL_MINOR_VERSION(version)

// Error: IGCL does not contain these definitions
```

**Issue 4: Enum Type Naming**
```csharp
// Tests use:
_ctl_property_type_flags_t.CTL_PROPERTY_TYPE_FLAG_DISPLAY
_ctl_init_flags_t.CTL_INIT_FLAG_USE_LEVEL_ZERO

// Error: Type names don't exist
```

**Issue 5: Unsafe Context Issues**
```csharp
// Some array accesses need unsafe context:
var adapters = _api.EnumerateAdapters(); // CS0214 error
```

### ?? Notes for Next Developer

**Key Patterns Observed**:
- Tests use `IDisposable` pattern with `IGCLApi.Initialize()` in constructor
- Skip tests when `_api == null` (no hardware/DLL)
- Most tests return success OR unsupported_feature error codes
- Use `unsafe` blocks extensively for pointer operations
- Two-pass pattern common: first call gets count, second call gets data

**Test Naming Convention**:
- `CtlFunctionName_ShouldDescribeExpectedBehavior`

```csharp
Assert.True(

);
```
